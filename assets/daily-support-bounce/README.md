# BTCUSDT 일봉 지지선 강세 캔들 백테스트

이 프로젝트는 일봉 OHLC CSV로 아래의 롱 전용 전략을 재현합니다. 실거래 주문을 내거나 데이터를 내려받지는 않습니다.

## 빠른 시작

Python 3.11 이상에서 다음을 실행합니다. Windows에서 `python` 명령이 없으면 `py -3` 또는 설치된 Python 실행 파일의 전체 경로를 `python` 대신 사용하세요.

```powershell
python -m pip install -r requirements.txt
python -m pytest -q
python btc_support_backtest.py C:\data\BTCUSDT_1d.csv --output-dir outputs\btc_support_run
```

CSV에는 아래 열이 반드시 있어야 합니다. 열 이름은 대소문자를 구분하지 않으며 `volume`은 선택입니다.

```csv
timestamp,open,high,low,close,volume
2024-01-01T00:00:00Z,42283.58,44175.37,42130.0,44156.22,12345.6
```

`timestamp`는 UTC ISO 날짜, Unix 초, Unix 밀리초를 지원합니다. 데이터는 시간순으로 정렬하며 중복 시점은 마지막 행만 사용합니다.

## 전략 정의

1. 어떤 봉 `p`의 저가가 좌측 3개 및 우측 3개 봉의 저가보다 모두 낮으면 스윙 저점입니다.
2. 우측 3개 봉이 종가를 낸 `p+3`부터만 그 스윙 저점을 사용할 수 있습니다. 이것이 미래 정보 방지 장치입니다.
3. 의사결정 봉 기준으로 과거 60봉 안의 확정 스윙 저점을 지지선 후보로 둡니다.
4. 당일 저가가 지지선의 ±0.3% 안에 있고, `close > open`이며, 종가가 `(low + 0.70 × (high-low))` 이상이면 신호입니다.
5. 신호가 확정된 다음 날 시가에 매수합니다. 미체결 신호가 있거나 포지션이 있으면 추가 신호는 무시합니다.
6. 손절 기준 가격은 `신호봉 저가 × 0.999`, 익절 기준 가격은 `진입 체결가 + 2.8 × (진입 체결가 - 손절 기준가)`입니다.

## 비용과 체결 가정

- 진입과 청산에 각각 0.03%의 불리한 슬리피지를 적용합니다.
- 수수료는 왕복 0.10%, 즉 진입·청산 각각 0.05%의 명목 금액으로 적용합니다.
- 갭 하락으로 손절가를 건너뛰면 시가에, 갭 상승으로 목표가를 넘기면 시가에 청산합니다. 이후 슬리피지를 더 적용합니다.
- 한 일봉 안에서 손절과 익절 모두 닿을 수 있으면 순서를 알 수 없으므로 보수적으로 **손절이 먼저**라고 처리합니다.
- 마지막 데이터 시점에 열린 포지션은 마지막 종가로 강제 청산합니다.

## 결과 해석

지정한 출력 폴더에는 다음 파일이 생성됩니다.

- `trades.csv`: 신호·지지선·진입·손절·목표·청산·순손익·R 배수를 포함한 전체 거래 기록
- `metrics.txt`: 거래 수, 승률, 평균 R, 기대값(R), Profit Factor, 최대 낙폭(R), 청산 연도별 성과
- `equity_curve.png`: 누적 R 기준 equity curve
- `r_distribution.png`: 거래별 순 R 분포

R은 초기 위험 대비 순손익입니다. 따라서 평균 R은 거래당 기대값이며, 예를 들어 `0.20R`이면 같은 조건의 거래를 매우 많이 반복한다는 가정에서 거래당 평균 위험금액의 20%를 벌었다는 뜻입니다. Profit Factor는 이익 R의 합을 손실 R의 절댓값 합으로 나눈 값입니다.

## 올바른 백테스트 절차

1. 규칙은 먼저 고정하고, 기간·지지선 폭·손익비를 결과를 보고 바꾸지 않습니다.
2. 개발 구간과 최종 검증 구간을 나눕니다. 예: 2021–2024로 설계한 뒤 2025–2026은 단 한 번의 아웃오브샘플 평가에 사용합니다.
3. 수수료와 슬리피지를 더 불리하게 바꿔도 결과가 유지되는지 확인합니다.
4. 거래 수, 최대 연속 손실, MDD를 확인하고, 실제 운용 가능한 금액과 리스크를 정합니다.
5. 파라미터를 반복 탐색했다면 별도의 완전히 미사용 기간으로 다시 검증합니다. 가장 좋아 보이는 설정 하나만 고르면 과최적화될 수 있습니다.

## 한계

일봉은 봉 내부의 가격 순서를 알 수 없습니다. 그래서 같은 날 손절과 목표가가 모두 닿으면 이 구현은 보수적으로 손절을 적용합니다. 더 정확한 검증을 위해서는 진입 후 1시간 또는 1분 OHLCV로 내려가 체결 순서를 재구성해야 합니다. 과거 성과는 미래 수익을 보장하지 않으며, 이 코드는 투자 조언이 아닙니다.
